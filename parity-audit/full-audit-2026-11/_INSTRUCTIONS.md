## Method — no skipping
1. Enumerate EVERY file in your assigned old-side scope (`find`/`ls` first,
   then read each one — including ones that look trivial). Your report must
   list every old file you covered; if a file is genuinely out of your scope,
   list it under "Delegated elsewhere" with the domain that owns it.
2. For each old function/endpoint/page: find the new counterpart (frontend
   action + Django view/selector/service, and for UI scope the new
   page/component). If NO counterpart exists, that is a finding (MISSING).
3. Compare at full depth:
   - endpoints: method, path, auth/permission gates, input validation (incl.
     min/max lengths, required fields), status codes, response shape/keys,
     error messages (Greek texts!), pagination, defaults
   - business logic: sorting orders, filters, counts, ranking/featured
     algorithms, date/time math, fee/price math, state machines
     (journey steps, subscription states, review moderation states)
   - side effects: emails (template, recipient, trigger), notifications,
     cache invalidation, denormalized-column updates, webhooks, crons
   - UI (this audit INCLUDES UI): every old page/component in scope vs the
     new one — forms (fields, validation messages, disabled states),
     flows/redirects, visible texts (Greek copy), breadcrumbs, empty states,
     counts shown, ordering of lists, links/hrefs, guards (logged-out, role)
4. Severity for each difference: CRITICAL (data loss/money/auth), HIGH
   (feature broken or missing), MEDIUM (wrong behavior/copy/ordering), LOW
   (cosmetic). When uncertain whether intentional → report it with a
   "possibly intentional?" note; NEVER silently drop it.
5. Take your time. Depth beats speed. Spot-checking is failure; this audit
   exists because earlier "it's all the same" claims missed real bugs.

  Django endpoints (the BEHAVIOR must match, the transport may differ).

  `frontend/src/lib/cache/revalidation.ts` helpers; Django Redis caches

  purged by signals in apps/{profiles,services,reviews}/signals.py.

  fallback regenerated by `yarn build:taxonomies`.
- Taxonomy FK columns (category_node etc.) alongside the old slug Charfields;
  `backfill_taxonomy_fks` command.
- Payments: `WORLDLINE_RECURRING_OVERRIDE_DAYS` test knob (default 0);
  renewals driven by Cardlink advice webhook, `billing-process-worldline-
  renewals` cron deliberately disabled; `backfill_payment_columns` command;
  admin payment-column fallbacks.
- Home "Δημοφιλείς Αναζητήσεις"/categories: shows up to 5 subcategories
  (max 2 rows) — user-requested change from old 3.

  and instant-open on remount (deliberate FIX of a bug the old app also has).
- Support dialog: neutral black 10-char hint, always-active button, red
  errors only after submit attempt (user-requested UX change).
- OAuth signup completion uses a hard window.location.assign redirect
  (deliberate fix of a frozen-loading bug).
- Admin panel UI was rebuilt; compare admin CAPABILITIES/actions and their
  effects, not pixel layout.
